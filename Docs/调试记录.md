# 调试记录

按步骤记录开发过程中实际遇到的问题：现象是什么、拿到什么证据、怎么定位、最后怎么改。

不是教程，是排查过程。

---

## 第 9 步 时钟与 SysTick

### 现象

HAL 的 `HAL_Delay` 时间不准，延时 1 秒实际明显偏长或偏短。

### 证据

串口打印 SysTick 计数和 HAL tick 计数，两者不同步。

### 判断

CubeMX 生成的时钟树默认是 HSI 8MHz，`SystemCoreClock` 还是 8MHz，但代码按 72MHz 算。

### 修改

外部晶振 8MHz 走 PLL 倍频到 72MHz，`SystemCoreClock` 同步更新。SysTick 配 1ms。

## 第 10 步 FreeRTOS 移植

### 现象 1：链接报重复定义

```
L6200E: Symbol SVC_Handler multiply defined (by port.o and stm32f1xx_it.o)
L6200E: Symbol PendSV_Handler multiply defined (by port.o and stm32f1xx_it.o)
```

### 判断

`port.c`（Cortex-M3 端口层）自己实现了 `SVC_Handler` 和 `PendSV_Handler`，而 CubeMX 生成的 `stm32f1xx_it.c` 里也有两个空函数。两个强符号冲突。

### 修改

删掉 `stm32f1xx_it.c` 里的这两个空函数，只留注释提醒。

关键点：**每次用 CubeMX 重新生成代码，这两个空函数都会回来**，必须再删一次。这个坑在后面的第 11、12、14 步反复出现。

### 现象 2：调度器起不来 / 任务不切换

### 判断

`SysTick_Handler` 里只有 `HAL_IncTick()`，FreeRTOS 的 tick 没被喂，`xPortSysTickHandler()` 从未调用。

### 修改

```c
void SysTick_Handler(void)
{
  HAL_IncTick();
  /* USER CODE BEGIN SysTick_IRQn 1 */
  if (xTaskGetSchedulerState() != taskSCHEDULER_NOT_STARTED)
  {
    xPortSysTickHandler();
  }
  /* USER CODE END SysTick_IRQn 1 */
}
```

两个要点：

1. 必须在 `USER CODE BEGIN/END` 之间，否则重新生成代码会被冲掉
2. 要判断调度器是否已启动，启动前调 `xPortSysTickHandler()` 会出问题

## 第 11 步 OLED 显示

### 现象

OLED 全黑，什么都不显示。代码逻辑检查过没发现问题。

### 证据

先看串口，不看屏：

```
[Boot] slot=0 crc=0xBC033E20 expect=0xB319CCF
[Boot] crc fail
[Boot] fallback to slot=1
[App] main=0x0801DAAD VTOR=0x0801C000
```

`VTOR=0x0801C000` 是 B 区地址。也就是说：**跑的根本不是刚烧进去的 A，而是回退到了 B**。B 是旧镜像，里面没有 OLED 代码，屏当然黑。

### 判断

重新编译 A 之后，A 区的 CRC32 变了，但元数据区里记的还是旧 CRC。Bootloader 上电校验 A 失败，按设计回退到 B。

这不是 OLED 的 bug，是 OTA 机制在正常工作。

### 修改

Bootloader 加"adopt"逻辑：如果当前运行的分区 CRC 和元数据不一致，但镜像本身能跑起来，就把当前 CRC 重新登记进元数据。

改完再烧：

```
[Boot] adopt crc_a=0xBC033E20 crc_b=0x9DED0DD8
[Boot] slot=0 crc=0xBC033E20 expect=0xBC033E20
[App] main=0x08006399 VTOR=0x08004000
[OLED] found 0x3C (write 0x78)
[OLED] task start
```

屏亮。

### 教训

**改完 App 重新烧录，CRC 一定变。** 烧录顺序必须是：先烧干净的 App（让在跑的 Bootloader 重新登记 CRC），再烧 Bootloader。反过来会回退到 B。

后来每次烧录完 App，串口第一件事就是确认 `VTOR=0x08004000`，不是就说明回退了。

## 第 12 步 4×4 矩阵键盘

### 现象

16 个键都能扫出来，串口有 `[KEY] x`，但按 2 出来的是 4，按 3 出来的是 7，整体错位。

### 证据

按左上角出 1 是对的，按右上角出的是 4，按左下角出的是 A。规律是行列对调。

### 判断

键盘的 8 根线分两组：4 行、4 列。代码里 PB0/PB1/PB3/PA1 当行（推挽输出），PB5/PA2/PB9/PB10 当列（上拉输入）。

接反之后，扫描逻辑变成矩阵转置：拉低的那组其实是列，读的那组其实是行，所以每个键的坐标都翻了个个儿。

### 修改

先分清哪 4 根是行、哪 4 根是列：

1. 万用表蜂鸣档，按左上角键，响的两根一根是第 1 行、一根是第 1 列
2. 按右上角键，响的两根一根是第 1 行、一根是第 4 列
3. 两两对比就能分组

然后行接输出脚，列接输入脚。四个角验证：1 / A / * / D。

### 附带问题：PB4、PB8 不能用

板子上 PB4 和 PB8 有其他占用。调整引脚：

| 功能 | 原计划 | 实际 |
|---|---|---|
| 行 3 | PB4 | PA1 |
| 列 1 | PB8 | PA2 |

代码里行、列各带一个端口数组，跨 GPIOA/GPIOB 也能处理：

```c
static GPIO_TypeDef *const s_row_port[4] = {GPIOB, GPIOB, GPIOB, GPIOA};
static const uint16_t s_row_pins[4]       = {GPIO_PIN_0, GPIO_PIN_1, GPIO_PIN_3, GPIO_PIN_1};
static GPIO_TypeDef *const s_col_port[4] = {GPIOB, GPIOA, GPIOB, GPIOB};
static const uint16_t s_col_pins[4]       = {GPIO_PIN_5, GPIO_PIN_2, GPIO_PIN_9, GPIO_PIN_10};
```

## 第 13 步 锁体驱动

### 情况

没有买电磁锁实物，按"继电器 + 高电平触发"写代码，用 PC0 输出验证。

```c
if (s_open && (int32_t)(xTaskGetTickCount() - s_deadline) >= 0)
```

没有实物，看串口和 PC0 电平：

```

...

```

## 第 14 步 AS608 指纹

### 现象 1：模块完全不应答

```
[FP] try 9600
[FP] no ack, raw 0:
[FP] try 57600
[FP] init=0 @57600
```

`raw 0` 表示一个字节都没收到。

### 判断

商品页写"配套例程波特率为 9600"，但**这块模块实际是 57600**。

### 修改

先试 57600，失败再退 9600，每个波特率试 3 轮。

### 现象 2：录入时 3.6 秒就返回 `enroll=255`

正常应该等 20 秒超时，实际 3.6 秒就返回，而且没有打印 `lift finger`。

### 判断

接收函数的超时是错的。原来这么写：

```c
static uint8_t as608_getc(uint8_t *b, uint32_t spin)
{
    while (spin--) { if (SR & RXNE) { *b = DR; return 0; } }
    return 1;
}
```

用空转次数当"毫秒"：20000 次空转在 72MHz 下大约 2.8ms，不是 10ms。所以标称 3000ms 的 `Img2Tz` 超时实际只有约 300ms，而处理一张 500dpi 图要 200~400ms，正好撞线。

### 修改

全部改用 `HAL_GetTick()` 算真实毫秒：

```c
static uint8_t as608_getc(uint8_t *b, uint32_t timeout_ms)
{
    uint32_t start = HAL_GetTick();
    while ((HAL_GetTick() - start) < timeout_ms)
    {
        if (s_uart.Instance->SR & USART_SR_RXNE) { *b = DR; return 0; }
    }
    return 1;
}
```

改完立刻通：`img1 ok → buf1=0 → img2 ok → buf2=0 → model=0 → store=0 → enroll=0`。

### 现象 3：想用 PC10-PC11 短接验证收发，短接后仍然收不到

### 判断

STM32F1 的 UART 只有 **1 字节**接收缓冲。测试包 12 字节，边发边回，第 2 个字节到达时第 1 个还没被读走，直接置 ORE（溢出）标志，后面的字节全部丢弃。

所以"12 字节回环失败"不能证明接收坏，是测试方法本身不成立。

### 修改

改成单字节回环自测：发 1 个 `0x55`，读状态寄存器和数据寄存器：

```
[FP] selftest sr=0x00C0 got=0x55 OK
```

`sr=0x00C0` 是 TXE+TC，`got=0x55` 说明 RX 收到了。

### 现象 4：模块跑一段时间后突然不应答

同一份代码，10:05 和 10:08 都能 `init=0 @57600`，10:11 变成 `raw 0`，断电重上又恢复。

### 修改

指纹任务里做成自恢复：初始化失败不退出，每 2 秒重试；搜索连续 5 次超时也回到初始化。

这样模块抽风时不用重新烧录，断电重上就能自己连回来。

### 最终日志

```
[FP] init=0 @57600
[FP] lib count=0
[FP] put finger
[FP] img1 ok
[FP] buf1=0
[FP] lift finger
[FP] put same finger again
[FP] img2 ok
[FP] buf2=0
[FP] model=0
[FP] store=0
[FP] enroll=0
[FP] lib count=1
[FP] match page=1 score=419
[LOCK] open 3000 ms
[LOCK] close
```

`score` 200 以上算匹配良好。

## 第 15 步 密码与三次锁定

### 现象 1：按 1 2 3 4 显示的是 4 个一样的数字

串口打出来是 `[PASS] key=2  len=2/6`、`[PASS] key=3  len=3/6`，看起来"按 2 出 2、按 3 出 3"，实际是**位数**在变，正好等于按的键值，误以为是对的。

**证据**：连按 5 个不同键，打印出来是 `1 2 3 4 5`，和按键顺序一样纯属巧合。
**判断**：日志打的是 `s_len` 而不是 `key`。
**修改**：改成 `printf("[PASS] key=%c  len=%u/%u\r\n", key, s_len, PASS_BUF_MAX)`。

### 现象 2：缓冲满之后按键彻底没反应

按到第 7 个键以后，怎么按都没有任何输出，像死机。

**证据**：键盘任务还在正常发队列，只是 `pass_handle_key()` 里 `if (s_len >= PASS_BUF_MAX) return;` 直接返回，一行日志都没有。
**判断**：静默丢弃。
**修改**：`PASS_BUF_MAX` 改成等于 `PASS_LEN`，满了打印 `[PASS] max digits`，用户知道该按 `#` 了。

### 现象 3：OLED 显示 5 行后跑一段就冻结

串口日志照常输出，屏幕停在某一帧不动。一开始怀疑死机或任务被饿死。

**证据**：加了 I2C 写失败计数 `s_err`，冻结时计数在涨，说明 I2C 传输返回了 `HAL_ERROR`。恢复后又能画，但整屏刷 8 页（1KB+）本身要几百毫秒。
**判断**：I2C 间歇挂死 + 每 300ms 整屏刷新，两个问题叠加。
**修改**：
1. `ssd1306_write_cmd/write_data` 检查 HAL 返回值累加 `s_err`，导出 `ssd1306_err_count()`；出错时 `ssd1306_bus_recover()` 做 `HAL_I2C_DeInit` + `HAL_I2C_Init`，同时清屏并清比对缓存强制重画
2. 改增量刷新：`ssd1306_refresh_page(page)` 只刷一页，`app_oled.c` 维护 `prev[5][24]` 文本比对，只有变化那页才动
3. 删掉每 300ms 变的"心跳行"，它一变动就抵消了增量刷新

改完 I2C 错误几乎不再出现。

## 第 16 步 ESP8266 + MQTT

### 现象 1：发 AT 完全没有回复

串口助手发 `AT`，一个字符都不回，怀疑模块坏。

**证据**：把 USB-TTL 直接接模块、手动发 `AT`，回 `OK`，模块是好的。
**判断**：H22/H23 两个跳线块还停在接 CH340 的位置，单片机的 USART3 根本没连到模块上；另外 SW2 拨码全 ON 时 IO0 被拉低，模块进烧录模式，AT 一概不回。
**修改**：H22、H23 都插 1-3、2-4，SW2 全 OFF。

### 现象 2：AT+MQTTCONN 回 ERROR

计划用现成的 MQTT AT 指令，一行搞定。

**证据**：`AT+GMR` 回 `AT version:1.7.4.0 (Jul 8 2020)`、`SDK version:3.0.5-dev`；`AT+MQTTCONN=?` 和 `AT+MQTTUSERCFG=?` 都回 `ERROR`。
**判断**：这版固件根本没编进 MQTT 指令。
**修改**：退回 `AT+CIPSEND`，自己按 MQTT 3.1.1 拼二进制报文。

### 现象 3：AT+GMR 的回复被截断成半句

偶尔能收到完整的 `AT version`，多数时候只有 `AT version:1.7`，后面没了。

**证据**：轮询版 `HAL_UART_Receive()` 收，日志长度忽长忽短。
**判断**：FreeRTOS 每 1ms 打断一次，F1 的接收寄存器只 1 字节深，字节到了没人搬走，第二个字节把第一个冲掉（ORE 溢出）。
**修改**：改中断接收 + 512 字节环形缓冲，`HAL_UART_RxCpltCallback` 里入环并重新 `HAL_UART_Receive_IT`（不重新挂只收一个字节）。

### 现象 4：TCP 连上立刻被断，`CONNECT|OK|CLOSED`

**证据**：连 broker 成功后串口是 `[MQTT] CONNECT|` → `[MQTT] OK|` → `[ESP] CLOSED|`，中间没有任何报文发出。
**判断**：`esp_at()` 收到 `OK` 还在死等剩下的超时时间，这几秒里没发 MQTT CONNECT，broker 等不到握手主动掐了 TCP。
**修改**：一看到 `OK`/`ERROR`/`FAIL`/`SEND OK` 立即返回，不等满超时。

### 现象 5：手机发了 open，门锁一声不响

MQTTX 显示消息已发出（绿色卡片），门锁侧连 `+IPD` 的回显都没有，`[MQTT] payload` 一行不出现。

**证据**：在 `mqtt_feed()` 开头打印缓冲长度和内容，数据确实收到了；`strstr(s_ipd, "+IPD,")` 返回 NULL。
**判断**：`s_ipd` 是 `static char s_ipd[256]`，`memcpy` 写数据但从来没写过 `'\0'`，`strstr` 一路扫到数组外读垃圾，永远找不到帧头。
**修改**：三处补 `s_ipd[s_ipd_len] = '\0';`（追加新数据后、丢帧头前垃圾后、处理完一帧后）。

### 现象 6：模块卡在等数据，之后所有 AT 都失效

`AT+CIPSEND=15` 之后没发够 15 字节，再发 `AT` 被当成数据吃掉，看起来模块死了，只能拔电。

**判断**：CIPSEND 之后模块进入等数据状态，只有够字节数或 `+++` 退出才能出来。
**修改**：等不到 `>` 或 `SEND OK` 时发 `+++` 再 `AT+RST` 恢复，实测能救回来，不用断电。

## 第 17 步 升级包传输与双镜像闭环

这一步排查时间最长，因为**两个问题叠在一起**：分区设计有缺陷，传输还丢字节。
先把分区修对，再修传输，才看得清。

### 现象 1：`apply: slot=B -> slot=A` 之后板子彻底没输出

**证据**：日志停在 `[OTA] apply: slot=B -> slot=A, 96 KB`，之后一个字节都不吐；
重新上电也只打印 Bootloader 的 `meta ok` 就没了。

**判断**：擦 A 槽时，CPU 正在执行的就是 A 区的代码。镜像链接在 0x08004000，
向量表里全是绝对地址，Bootloader 把 VTOR 指到 B 只是换了个"表的位置"，
表里的函数地址仍指向 A 区。所以擦 A 等于把正在跑的代码擦了。

**修改**：新增 `AppB.uvprojx`（IROM1 = 0x0801C000，与 App 同源），
让每个槽跑自己链接的镜像。验证 `[App] main=0x0801F84D VTOR=0x0801C000`。

### 现象 2：升级成功后重启又变回旧版本

**证据**：升级完 `meta saved: slot=1 trial=1`，重启却回滚，`boot_count` 一路加。

**判断**：`system_stm32f1xx.c` 里 `USER_VECT_TAB_ADDRESS` 让 `SystemInit()`
把 `SCB->VTOR` 无条件写回 0x08004000，App 里"VTOR 是否等于自己所在槽"的判定
永远不成立，`confirmed` 永远执行不到。

**修改**：注释掉那个宏，改在 `main.c` 的 `USER CODE BEGIN 1` 兜底：
只有 VTOR 既不是 A 也不是 B 时才置 A。

### 现象 3：串口发 `D` 一点反应都没有

**证据**：串口助手连发两次 `D`，板子没有任何回显，但其他功能正常。

**判断**：CubeMX 里 USART1 只配了发送，`USART1_IRQn` 在 NVIC 里是关的，
`stm32f1xx_it.c` 里也没有 `USART1_IRQHandler`。`HAL_UART_Receive_IT` 虽然调用成功，
但中断永远进不来，环形缓冲一直是空的。

**修改**：`ota_task_start()` 里补 `HAL_NVIC_SetPriority/EnableIRQ(USART1_IRQn, 6, 0)`，
并在 `app_ota.c` 里定义 `USART1_IRQHandler()` 调 `HAL_UART_IRQHandler(&huart1)`。

### 现象 4：30400 字节的包只收到 23837 字节

**证据**：`[OTA] recv 23837 bytes`，比文件少 6563；发之前还夹了几个杂字节。

**判断**：任务里直接轮询 `USART1->SR`，每攒 256 字节写一页 W25Q 要 3~4ms，
这期间 115200 下会进来约 40 个字节，USART 只有 1 字节接收寄存器，溢出就丢。

**修改**：接收改成中断 + 2048 字节环形缓冲，接收中断只负责搬运，任务慢慢落盘；
缓冲满时 `s_rx_drop++` 并在收包结束打印；空闲判定 2 秒 → 5 秒。改完 `dropped=0`。

### 现象 5：包只传了一半，`verify ok` 却通过了，把 A 槽刷成砖

**证据**：`recv 23837 bytes` 之后 `apply` 照样 `verify ok`，复位后只打到 `meta ok` 就挂。

**判断**：verify 的基准是"当前运行槽"，也就是拿**残缺的包**跟**照残缺包写进去的槽**比，
两边当然一致。校验基准选错，自己跟自己比永远通过。

**修改**：基准改成 W25Q 暂存区，逐块 `memcmp`；擦除前再加一道包头检查
（栈顶必须在 SRAM、复位向量必须落在目标槽、不能全 0xFF）。

### 现象 6：烧完固件板子完全静默

**证据**：拉 DTR 无反应，串口一个字节都没有；按一下 RESET 立刻有完整启动日志。

**判断**：Keil 下载完不会自动复位运行，MCU 还停在调试器放下的状态。

**修改**：按 RESET 或断电重上电。判断依据就是"复位后有日志"，说明程序本身没问题。

### 现象 7：W25Q 读回来的数据偶发错误，apply 后 CRC 对不上

**判断**：逐字节 `HAL_SPI_TransmitReceive` 搬 96KB 要 98304 次事务，任一次失败就
静默返回 `0xFF`，数据被写坏。

**修改**：新增 `w25q_read_blk` / `w25q_write_blk`，一次搬 256 字节、失败整块重试 3 次；
SPI2 分频 2 → 4（18MHz → 9MHz）。

### 回滚实验（不是踩坑，是主动验证）

造一个"能过 CRC、一跑就崩"的坏包（复位向量指到槽尾 0xFF 区），
实测三次试启动失败后 `rollback 1 -> 0`，旧镜像正常启动。

## 通用经验

1. **先看串口，别先看现象。** OLED 黑屏那次，串口一行 `fallback to slot=1` 就把问题从"显示"转到了"启动分区"。
2. **CubeMX 重新生成代码后必查三处**：`SVC_Handler`/`PendSV_Handler` 是否回来了、`SysTick_Handler` 的 FreeRTOS tick 还在不在、`USER CODE` 段里的初始化调用是否还在。
3. **超时别用空转次数。** 编译器优化等级一变，空转的真实时长就变，必须用 tick 算。
4. **测试方法本身也要验证。** 12 字节回环失败差点被当成硬件坏，实际是 UART 只有 1 字节缓冲。
5. **硬件问题用仪器定位，别猜。** 逻辑分析仪抓到 `EF 01 FF FF FF FF 01 00 07 13 00 00 00 00 00 1B`，直接证明 MCU 发送链路正常，把范围缩到模块侧。
6. **`memcpy` 之后自己补 `'\0'`。** 凡是可能交给 `strstr`/`printf %s` 的缓冲区，`memcpy` 不写结束符，字符串函数就会扫到数组外读垃圾，表现是"功能没报错但永远不生效"。
7. **校验的基准必须是独立来源。** 拿"写进去的东西"跟"要写的东西"比，永远通过；
   verify 已经爆过一次（残缺包把 A 槽刷成砖），所以基准换成 W25Q 暂存区 + 包头合法性。
8. **擦 Flash 之前先问：这份代码现在从哪取指？** 擦自己的槽必死，
   A/B 双分区的前提是两个槽各自按自己的地址链接，否则"切换分区"只是换了张表。
9. **接口没反应，先确认中断/时钟真的使能了。** CubeMX 只配发送就不会有接收中断，
   没有 `NVIC_EnableIRQ` 的话 `HAL_UART_Receive_IT` 调用成功也是空转。
10. **接 AT 类模块先查能力再定方案。** `AT+GMR` 看固件版本，`AT+XXXX=?` 探指令是否存在，别写完一整套调用才发现固件里没这条指令。
