# 平台改版交接（换板 / 换芯片）

> 写于 2026-11-18 15:35。1.0 已验收通过，2.0 的锁体开发暂停，先解决硬件平台。
> 这份文档的目的：把"现在有什么、占了多少资源、换板必须满足什么、代码要改哪里"一次写清，
> 换板期间不用回头翻代码。

---

## 一、为什么要换板

现在用的是教学板（STM32F103RCT6）。它能跑通 1.0，但继续往上做处处受限：

| 问题 | 具体表现 |
|---|---|
| 引脚被板载外设占用 | 板上有 LCD、蜂鸣器、EEPROM、按键等一堆外设，可用引脚被切得七零八落；PB4 要 `__HAL_AFIO_REMAP_SWJ_NOJTAG()` 才能当普通 IO 用 |
| 引脚冲突靠"绕"解决 | 键盘列 1 原本 PB10，因为要让给 ESP8266 的 USART3 才改到 PB4；PB3 也是调试口 |
| 串口不够 | 只有 3 个可用：USART1 调试、USART3 ESP、UART4 指纹，再加外设就没地方了 |
| Flash 很紧 | 256KB 里 212KB 被分区占掉（83%），想给日志/双版本留空间就得动分区表 |
| 接线靠跳线帽 | H22/H23 跳线块选串口、SW2 拨码选模式，插错一次排查半天（这一步踩过坑） |
| 体积大 | 整块板比产品外壳还大，做不出"门锁"的形态 |

结论：不是代码写不下去，是**平台的余量已经用完**。换一块"引脚全引出、没有板载外设抢资源"的板子，
后面 2.0 的锁体、日志、UI 才有地方放。

## 三、当前引脚占用（换板时要一对一搬过去）

| 功能 | 引脚 | 说明 |
|---|---|---|
| 调试串口 USART1 | PA9 TX / PA10 RX | printf + OTA 收包（中断 + 2KB 环形缓冲） |
| ESP8266 USART3 | PB10 TX / PB11 RX | 115200，AT 指令 + 手写 MQTT |
| AS608 UART4 | PC10 TX / PC11 RX | 57600，模块自己初始化（不在 CubeMX 里） |
| OLED I2C1 | PB6 SCL / PB7 SDA | 400kHz，SSD1306 |
| W25Q128 SPI2 | PB13 SCK / PB14 MISO / PB15 MOSI，PB12 CS | 9MHz，OTA 暂存区 |
| 键盘 行 R1–R4 | PB0 / PB1 / PB3 / PA1 | 推挽输出，默认高 |
| 键盘 列 C1–C4 | PB4 / PB9 / PA2 / PB5 | 上拉输入（PB4 需 NOJTAG remap） |
| 锁体 | PC0 | 高电平吸合（待接 5V 继电器模块 + 12V 电磁锁） |
| 启动失败指示 | PA15 | Bootloader 双槽都坏时快闪 |

合计：3 个串口、1 个 SPI、1 个 I2C、13 个普通 IO。

## 四、Flash / RAM 账

| 项 | 大小 | 占比 |
|---|---|---|
| Bootloader | 16KB（0x08000000） | 6% |
| App-A | 96KB（0x08004000） | 37% |
| App-B | 96KB（0x0801C000） | 37% |
| 元数据 | 4KB（0x08034000） | 2% |
| 合计占用 | **212KB / 256KB** | **83%** |

RAM 48KB：FreeRTOS 堆 16KB，其余静态区约 22KB（含各任务栈），余量约 10KB。

这套分区在 F103 上已经贴顶，2.0 想加日志缓存、UI 缓冲、更大的 MQTT 缓冲就不够了。

## 五、换板硬指标

选板子先按这几条卡，缺一条后面都会别扭：

| 指标 | 最低 | 建议 | 原因 |
|---|---|---|---|
| Flash | 256KB | **512KB** | A/B 双分区各 128KB + Bootloader 32KB + 元数据，还要给日志留 |
| RAM | 48KB | **96KB 以上** | FreeRTOS 堆加大、MQTT/日志缓冲、OLED 缓冲 |
| 串口 | 3 个 | **4 个以上** | 调试 / ESP / 指纹，最好再留一个给扩展 |
| SPI | 1 | 2 | W25Q + 预留（屏/传感器） |
| I2C | 1 | 1 | OLED |
| 可用 IO | 16 | **24 以上** | 键盘 8 + 锁 2 + 指示灯 + 预留 |
| 板型 | 引脚全引出 | **核心板/最小系统板** | 不能有板载外设抢引脚 |

## 六、候选芯片对比

| 方案 | Flash/RAM | 主频/内核 | 迁移成本 | 价格（核心板） | 适合谁 |
|---|---|---|---|---|---|
| **STM32F103VET6** | 512KB / 64KB | 72MHz / M3 | **最低**：同系列，CubeMX 换型号即可，Flash 2KB 页擦除不变 | ~25 元 | 只想解决引脚和 Flash 不够 |
| **STM32F407VET6** | 512KB / 192KB | 168MHz / M4F | 中：HAL 换 F4、时钟树重配、**Flash 擦除要改成扇区**（16/64/128KB） | ~40 元 | 想升级性能又要控制工作量（推荐） |
| STM32F407VGT6 | 1MB / 192KB | 168MHz / M4F | 同上 | ~60 元 | 想把日志、多版本、UI 一次做足 |
| STM32F401CCU6 | 256KB / 64KB | 84MHz / M4F | 中 | ~15 元 | 预算优先，但 Flash 仍紧（A/B 只能各 96KB） |
| ESP32-S3 | 8MB / 512KB | 240MHz 双核 | **重写**：原生分区 OTA，等于不用自己实现 | ~30 元 | 不推荐（论文价值反而降低） |

### 我的判断

- **要"改动最小、稳住 1.0"→ F103VET6。** 同一份 HAL，CubeMX 里把型号一换、引脚重新分配，
  OTA 代码一行不用改（Flash 还是 2KB 页）。风险最低，两天能迁完。
- **要"平台升级 + 论文有内容"→ F407VET6。** 多出来的是实打实的能力：168MHz + FPU、
  192KB RAM、6 个串口、Flash 512KB。而且换内核这件事本身能写成论文里的一节：
  **从 F1 的 2KB 页擦除迁移到 F4 的扇区擦除，Bootloader 的分区表和擦除逻辑怎么改**。
  这是"能做出来的工作量"，不是凑字数。
- **不建议换到 ESP32。** 它自带 OTA 分区，等于把项目最核心的那部分交给 SDK，
  论文最值钱的一章就没了。

我的倾向：**F407VET6**。理由是这个项目已经从"点亮外设"走到"做可靠性设计"，
再往上做 2.0（网络下载固件、日志、UI）需要的是 RAM 和外设数量，F103 的 64KB RAM 会一直卡着；
而 F407 的代价主要是"Flash 擦除逻辑要改"，这部分恰好是我们最熟的一块。

## 七、换板迁移清单

按这个顺序做，每步都能单独验证，不会一次改太多查不出来：

1. **定板型 → 买核心板**（推荐 F407VET6 最小系统板，引脚全引出，不画 PCB 也能做）
2. **列新引脚表**：把第三节那张表一对一映射到新板，先写在文档里再动手
3. **CubeMX 新建工程**：时钟树、3 个串口、SPI2、I2C1、GPIO，生成后立刻检查
   `SVC_Handler`/`PendSV_Handler` 是否重复、`SysTick_Handler` 里的 FreeRTOS tick 是否还在
4. **先跑最小系统**：点灯 + printf，确认时钟和串口对
5. **搬 Bootloader**：F4 的 Flash 扇区擦除逻辑要重写（这是最大的改动点），
   分区表按新 Flash 大小重新规划
6. **搬 App**：外设驱动逐个接（OLED → 键盘 → 锁 → 指纹 → ESP → W25Q），
   建议每接一个就跑一次对应的 `test-*` 验收
7. **回归 1.0 三条**：双分区 A→B→A、坏包回滚、MQTT 远程开锁
8. **重新打 release**：hex 变了，`v1.0` 要说明"硬件平台从 F103RCT6 换到 XXX"，
   或者直接发 `v1.1`

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| F4 的 Flash 扇区擦除写错，把 Bootloader 自己擦了 | 先在纸上画扇区表，擦除函数加地址范围断言，第一次用调试器单步 |
| 新板子时钟配错，串口波特率全偏 | 先跑 printf 自检，波特率不对立刻能看出来 |
| 引脚重映射后外设不工作 | 每接一个模块就单独打日志验证，别一次全接上 |
| 换板期间 1.0 无法演示 | 保留旧板 + 旧 hex（`门锁发布包_v1.0`），旧板别拆，随时能演示 |
| 时间不够 | 退路是 F103VET6：同系列迁移，两天能完成，功能与现在完全等价 |
