# 回滚实验：新镜像起不来时，Bootloader 自己退回旧槽

## 目的

验证 A/B 双分区的最后一道保险：升级上去的镜像如果跑不起来（App 永远确认不了），
Bootloader 连续几次试启动失败后会自动切回上一个能用的槽。

## 做法

1. 正常升级一次，让 B 槽装上一个能跑的 AppB 镜像；
2. 用 `Tools/make_bad_pkg.py` 把 AppB.bin 的复位向量改到 B 槽尾部的 0xFF 区，
   生成 `AppB_bad.bin`。这样包头看起来合法（栈顶在 SRAM、复位向量在槽区间内），
   Bootloader 的整槽 CRC 也能通过，但一进去就是 HardFault，App 永远走不到确认那一步；
3. 把这个坏包按正常流程升进 B 槽（串口发 D 收包，发 A 应用+复位）。

## 实测日志

```
[OTA] pkg sp=0x20005980 pc=0x0802C101 -> slot=B     坏包通过包头校验
[OTA] apply: slot=A -> slot=B, 96 KB
[Boot] adopt crc_a=0xFECF8189 crc_b=0x4E6E6EF7
                                    ↑ 之后没有 App 输出，卡在 HardFault

第 1 次复位：magic=0x5A5AA5A5 slot=1 trial=1 cnt=1
            [Boot] trial, boot_count=2              又试一次，还是崩

第 2 次复位：magic=0x5A5AA5A5 slot=1 trial=1 cnt=2
            [Boot] trial, boot_count=3

第 3 次复位：magic=0x5A5AA5A5 slot=1 trial=1 cnt=3
            [Boot] rollback 1 -> 0                  连续三次失败，退回 A 槽
            [App] main=0x080078A5 VTOR=0x08004000
            [App] boot: vtor=0x08004000 slot=0 trial=0 cnt=0
            [LOCK] start, state=CLOSED
            ...
            [MQTT] mqtt ready @ broker.hivemq.com   旧镜像正常跑起来
```

## 结论

- `trial=1` 期间，每次上电 `boot_count` 加一，加满 3 次就 `rollback`，把
  `active_slot` 改回另一个槽、`trial` 清零、计数清零，然后跳旧槽；
- 回滚后旧镜像照常启动，指纹、键盘、MQTT 全部正常，说明退回去的是完整可用的一份；
- 坏包能骗过 CRC（内容自洽）但骗不过"能不能确认"这一步 —— 这正是试启动机制存在的意义。
